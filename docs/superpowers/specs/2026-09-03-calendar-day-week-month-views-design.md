# 日曆日／週／月視角設計規格

## 目標

將目前只能按月瀏覽的「月曆」擴充為可切換日、週、月視角的「日曆」，讓使用者能依不同時間尺度查看記事，同時保留既有搜尋篩選、記事詳情、類別顏色及月視角單日清單流程。

成功條件如下：

- 使用者可在日曆卡片標題列右側、期間導覽左側切換「日／週／月」。
- 切換視角時保留目前焦點日期；左右箭頭依視角移動一天、一週或一個月。
- 日視角以完整摘要卡顯示單日記事；週視角在 1024px 以上顯示七欄，在手機與平板窄版顯示七個直向日期區段；月視角維持現有七欄月曆格。
- 三種視角都只顯示符合目前搜尋與篩選條件的記事，期間計數也只計算符合結果。
- 日與週視角可直接新增指定日期的記事，開啟表單時預填該日期。
- 最後使用的日／週／月模式保存在目前裝置，但焦點日期不跨主頁切換或重新載入保存。
- 不變更 Google Sheet schema，也不遷移既有記事資料。

## 名稱與範圍

### 使用者介面名稱

- 左側導覽、行動版底部導覽、頁面大標題及時間軸／日曆主切換器中的「月曆」一律改為「日曆」。
- 單日清單的返回文字改為「返回日曆」。記事詳情依開啟來源顯示「返回時間軸」或「返回日曆」；三種日曆視角及月視角單日清單都屬於日曆來源。
- 程式內既有 `calendar` 頁面識別值與 `daily-journal:view` 儲存值維持不變，避免破壞已發布版本的主檢視偏好。
- 日、週、月模式在程式內使用 `day | week | month`；介面使用台灣慣用的「週」，不使用「周」。

### 本次包含

- 日／週／月分段切換器與響應式排列。
- 共用焦點日期、期間導覽、標題、符合結果計數及載入／錯誤狀態。
- 日視角、週視角及既有月視角的整合。
- 指定日期新增記事及表單日期預填。
- 精確日期區間查詢 API。
- 模式偏好、鍵盤操作、基本無障礙及自動化測試。

### 本次不包含

- 時段式行程格、拖放、重複記事或排程功能。
- 週視角卡片內直接編輯或刪除；使用者先開啟記事詳情再操作。
- 月視角空白日期的直接新增入口；空白日期維持目前不可進入單日清單的行為。
- 以左右滑動手勢切換期間。
- 將焦點日期保存到 `localStorage`、網址或伺服器。
- Google Sheet 欄位或資料格式變更。

## 已確認的方案

採用「統一日期區間 API＋三個獨立視角元件」。日曆頁以一個焦點日期推導目前期間，透過同一個區間 API 精確取得一天、七天或一個月的資料，再交由日、週、月元件呈現。

未採用的方案：

- 只沿用每月 API：日視角會過度取回整月資料，跨月週次還需要兩次請求與額外競態處理。
- 最大幅度重用既有時間軸：改動較少，但無法提供已確認的桌面七欄週視角，日、週、月的資訊密度也會不一致。

## 核心狀態與日期規則

日曆頁只以兩個值決定顯示內容：

- `mode`：`day`、`week` 或 `month`。
- `anchorDate`：格式為 `YYYY-MM-DD` 的焦點日期。

不得另外保存彼此可能不同步的目前月份、週起日或日視角日期。它們都由 `anchorDate` 計算。

### 初始化與保存

- 新增獨立的 `daily-journal:calendar-mode` 本機儲存鍵，只保存日／週／月模式。
- 沒有偏好、偏好無效或瀏覽器拒絕存取儲存空間時，安全回退為 `month`。
- 第一次進入日曆、從其他主頁重新進入日曆、重新整理、重新登入或更換資料空間後，`anchorDate` 都設為記事時區的今天。
- 從記事詳情或月視角的既有單日清單返回，屬於日曆內的深入與返回，不重設模式或焦點日期，並沿用既有捲動位置還原行為。

### 模式與期間切換

- 切換日、週、月時保留同一個 `anchorDate`。
- 日視角左右箭頭移動前後一天。
- 週視角左右箭頭移動前後七天；每週固定為週一到週日。
- 月視角左右箭頭移動前後一個月，盡量保留日數；目標月份沒有該日時取該月最後一天。例如 2026-01-31 的下一個月為 2026-02-28。
- 「今天」只將 `anchorDate` 設為記事時區的今天，不改變目前模式。
- 所有日期運算以純 `YYYY-MM-DD` 日曆日期及 UTC 日曆算術完成，避免瀏覽器本地時區與日光節約時間造成日期偏移。

### 日別互動與焦點

- 使用者在週或月視角操作某一天的新增按鈕、日期、記事或更多記事入口時，該日先成為新的 `anchorDate`。
- 月視角只有含符合條件記事的日期可進入既有單日清單；進入後不把模式切成 `day`。
- 從單日清單或記事詳情返回後，原視角仍以該日期作為焦點；若之後切換模式，新視角也以該日期推導期間。

## 共用日曆外框

日曆卡片由共用外框負責期間資訊與控制，再依 `mode` 呈現個別內容元件。

### 桌面與平板標題列

標題列由左至右排列：

1. 期間標題與符合結果計數。
2. 位於需求圖紅框位置的「日｜週｜月」分段切換器。
3. 上一期、今天、下一期控制組。

分段切換器沿用現有控制組的灰色底座。三個按鈕等高；目前模式以白底、藍字及輕陰影表示。按鈕使用 `aria-pressed`，外層提供「日曆檢視模式」無障礙名稱。

期間標題格式：

- 日：`2026年9月3日 星期四`
- 同年週：`2026年8月31日－9月6日`
- 跨年週：`2026年12月28日－2027年1月3日`
- 月：`2026年9月`

副標依模式顯示「本日共有 N 則記事」、「本週共有 N 則記事」或「本月共有 N 則記事」。`N` 是目前期間內符合所有搜尋與篩選條件的記事總數。

### 手機標題列

- 期間標題與計數、分段切換器、期間導覽依序換行。
- 分段切換器以三個等寬按鈕填滿可用寬度。
- 所有觸控目標高度至少 44px。
- 即使行動版外層頁面大標題依現有設計隱藏，日曆卡片內的期間標題與控制仍完整顯示。

### 導覽與狀態公告

- 左右箭頭的無障礙名稱依模式為「前一天／後一天」、「上一週／下一週」或「上一個月／下一個月」。
- 期間標題在模式或日期改變後以禮貌型 live region 公告，但不搶走鍵盤焦點。
- 模式切換後鍵盤焦點留在剛按下的模式按鈕。

## 日視角

- 顯示 `anchorDate` 當天所有符合條件的記事。
- 記事沿用現有單日排序：建立時間由新到舊，同時間以 ID 固定排序。
- 每則記事重用既有完整摘要卡資訊，包括建立時間、類別、標題、最多三行內文摘要與全部標籤；類別自訂色維持一致。
- 日視角的完整卡片保留既有開啟詳情、編輯與刪除操作。
- 內容區固定提供「新增這天的記事」，不論當日是否已有記事；開啟表單時預填 `anchorDate`。
- 沒有結果時顯示「這天還沒有符合條件的記事」及相同新增入口。若目前有啟用篩選，不自動清除篩選。

## 週視角

### 寬版桌面

- 1024px 以上依週一至週日顯示七欄，欄位 DOM 順序也固定為週一至週日。
- 每欄是獨立日期區段，包含星期、月／日、符合結果數、今日標示及新增入口。
- 七欄使用 `align-items: start`，單一日期展開時不強制其他日期卡片等高。
- 週視角不使用 ARIA grid；以有標題的日期區段及文章清單表達結構，讓響應式改成直向後仍維持相同語意與鍵盤順序。

### 手機與平板窄版

- 不壓縮七欄，也不使用水平捲動。
- 1023px 以下將週一至週日改為七個由上到下排列的日期區段，內容及操作與寬版桌面相同。

### 週摘要卡與展開

- 每則精簡摘要卡顯示類別、標題、最多兩行內文摘要及前兩個標籤；有更多標籤時不另外顯示數量。
- 點選摘要卡開啟既有記事詳情。週卡片本身不提供編輯或刪除按鈕。
- 每個日期先顯示最多 3 則記事。超過時顯示「還有 N 則」；按下後在原日期區段展開全部，並改為可操作的「收合」。
- 展開狀態以日期為索引，但在切換模式、移動期間或變更搜尋篩選時全部重設。
- 每欄固定提供新增入口並預填該欄日期。沒有結果時顯示「這天還沒有符合條件的記事」，仍可新增。

## 月視角與單日清單

- 保留現有週一至週日七欄月曆格、每格先顯示 2 則記事及「還有 N 則」選擇視窗。
- 月視角仍只呈現當月日期，不在前後空白格補上相鄰月份日期。
- `anchorDate` 的日期格使用焦點樣式；記事時區的今天另有可同時存在的今日標示。
- 只有含符合條件記事的日期可開啟既有獨立單日清單；空白日期維持不可點選，也不在月格內新增記事。
- 月格中的記事按鈕仍直接開啟記事詳情，不先開啟單日清單。
- 「還有 N 則」仍開啟既有記事選擇視窗，選定後進入詳情。
- 單日清單沿用現有完整時間軸卡片、搜尋篩選及返回捲動位置；返回文字統一為「返回日曆」。從單日清單開啟的記事詳情也以日曆為返回來源。

## 元件邊界

為避免既有 `CalendarView` 同時負責日期運算、資料請求及三種版面，拆分為下列職責：

- 日曆頁面容器：保存 `mode`、`anchorDate`、載入資料與深入頁狀態，計算查詢範圍並協調 CRUD 後重新載入。
- 共用日曆外框：呈現期間標題、計數、分段切換器、期間導覽、載入與錯誤狀態。
- 日視角元件：呈現單日完整摘要卡與指定日期新增入口。
- 週視角元件：呈現七個日期區段、精簡摘要卡及各日展開狀態。
- 月視角元件：由現有月曆格抽出，保留日期、更多記事與選擇視窗行為。
- 週摘要卡：只負責精簡顯示及開啟詳情，不承擔資料查詢或 mutation。
- 日期工具：負責日／週／月範圍、週一起日、日期位移、月底鉗制與標題格式化。
- 日曆模式偏好工具：只驗證、讀取及保存 `day | week | month`。

共用外框與三種視角透過明確 props 溝通，不直接呼叫 API。日視角重用既有完整記事卡；月視角重用既有月格記事、類別顏色及更多記事視窗；週摘要卡保持獨立，避免用大量 CSS 覆寫把時間軸卡片塞入七欄。

## API 與領域資料流

### 新增請求

在共用 `ApiRequest` 新增：

```ts
{
  action: 'getEntriesForRange'
  from: string
  to: string
  filter: EntryFilterCriteria
}
```

回應沿用現有 `DailyEntries[]`：

```ts
type DailyEntries = {
  date: string
  entries: Entry[]
}
```

### 區間規則

- `from` 與 `to` 都是含頭含尾的有效 `YYYY-MM-DD` 日期。
- `from` 不得晚於 `to`。
- 一次請求最多包含 42 個日曆日，足以涵蓋一天、七天與任何單月，同時防止無界限查詢。
- API 先套用既有關鍵字、篩選日期、分類及標籤條件，再與顯示期間取交集。
- 回應只包含至少有一則符合記事的日期；空白日期由前端依期間補齊。
- 日期群組依日期由早到晚排列；同日記事沿用現有建立時間由新到舊及 ID 固定排序。
- 日、週、月分別送出 1 天、7 天及當月第一日至最後一日。跨月或跨年週次仍只送出一次請求。
- 區間結果不分頁；這與目前月視角會取回當月完整記事的行為一致，42 天上限負責限制時間範圍。

### 舊 API 相容性

已發布的舊版前端可能仍在開啟中的分頁或快取中呼叫 `getEntriesForDate`、`getMonthlyEntries` 與 `getMonthlyEntryCounts`，因此這三個動作暫時保留。新版日曆與單日清單統一改用 `getEntriesForRange`；舊 service 方法可委派給相同的區間查詢核心，避免兩套篩選與排序規則分歧。

### 前端查詢流程

1. 依 `mode + anchorDate` 計算 `from` 與 `to`。
2. 組合目前 `EntryFilterCriteria` 並建立可識別目前請求的 range key。
3. 將內容區切換為該 range key 的載入狀態，不把上一期間資料顯示在新標題下。
4. 呼叫 `getEntriesForRange`。
5. 同時符合目前工作區 epoch、最後請求 ID 與目前 range key 時才採納回應。
6. 以回應計算符合結果總數，並交給目前模式元件呈現。

進入月視角的單日清單時，使用相同 API 查詢 `from = to = selectedDate`。單日清單有獨立請求識別，不能與背景日曆期間請求互相覆蓋。

## 新增、編輯與刪除

- `EntryForm` 新增選填 `initialDate`。編輯既有記事時永遠以記事本身的 `entryDate` 為準；建立新記事時依序使用 `initialDate` 或記事時區的今天。
- 日視角新增傳入 `anchorDate`；週視角新增傳入該欄日期；全站既有新增按鈕仍使用今天。
- 成功新增、編輯或刪除後保留目前 `mode` 與 `anchorDate`，透過既有 revision 機制重新查詢目前期間。
- 若新增或編輯後的記事不在目前期間，或不符合目前篩選條件，結果中不顯示該記事，也不自動清除篩選。
- 操作失敗時沿用既有表單或刪除確認視窗錯誤，介面不提早關閉，也不先從目前期間移除資料。
- 從單日清單或記事詳情完成 mutation 後，返回日曆時不得顯示 mutation 前的舊期間資料。

## 載入、錯誤與競態處理

### 載入

- 日期、模式或篩選改變後，標題與控制列立即反映新狀態。
- 內容區設定 `aria-busy="true"` 並顯示既有查詢中提示；上一期間記事不在新標題下暫留。
- 期間控制維持可操作，允許使用者快速切換；只有最後一次請求可以更新畫面。

### 查詢錯誤

- 一般區間查詢失敗時保留目前模式、焦點日期與控制列，在日曆內容區顯示明確錯誤及「重新載入」。
- 重試只重送目前期間與目前篩選，不回到今天或月視角。
- 一般日曆區間錯誤只寫入日曆內容區，不再同時寫入全域錯誤；登入失效則交由既有中央工作階段流程切換狀態。
- 快速切換、登出、重新登入或更換資料空間後到達的舊回應，必須由工作區 epoch、請求 ID 與 range key 共同拒絕。

### 空白結果

- 日視角與週視角各日期區段使用「這天還沒有符合條件的記事」。
- 月視角維持完整月格，不以全頁空白狀態取代月曆。
- 空白結果不是錯誤，也不顯示重試按鈕。

## 無障礙與響應式要求

- 所有模式、期間、展開、收合、新增及記事按鈕皆可使用鍵盤到達。
- 分段切換器使用按鈕與 `aria-pressed`，不可只靠顏色表達目前模式。
- 週日期區段以唯一標題關聯其記事清單；「還有 N 則」使用 `aria-expanded` 並關聯被展開的內容。
- 今日、焦點日期及目前模式皆同時具備非顏色提示。
- 375px 寬度：週視角為七個直向日期區段，無水平頁面溢位。
- 768px 至 1023px：即使固定側欄已顯示，週視角仍為七個直向日期區段，內容不被壓縮或水平裁切。
- 1024px 及以上：週視角為七欄，摘要文字正確截斷，欄內按鈕不超出邊界；分段切換器位於期間標題與期間導覽之間，符合需求圖紅框位置。
- 觸控目標至少 44px；文字放大與長標題不得遮住導覽按鈕。

## 測試策略

### 日期工具單元測試

- 任意日期正確取得週一與週日。
- 週範圍跨月、跨年及閏年。
- 日位移與七日位移。
- 月位移保留日數及月底鉗制，包括 1 月 31 日、閏年 2 月 29 日。
- 日、週、月查詢範圍及三種期間標題。

### 領域與 API 測試

- 區間含頭含尾、空白結果及 42 天上限。
- 無效日期、不存在日期、反向範圍及超過上限皆回傳驗證錯誤。
- 顯示期間與篩選日期取交集，並同時套用關鍵字、分類與標籤。
- 日期群組由早到晚、同日記事由新到舊。
- dispatcher 接受新動作，未知或畸形輸入仍安全拒絕。
- 三個舊日期／月份動作維持既有回應與驗證行為。

### 元件測試

- 三段切換器的 `aria-pressed`、鍵盤操作及模式回呼。
- 每種模式的標題、符合結果計數、上一期、下一期與今天。
- 日視角完整摘要卡、空白狀態及指定日期新增。
- 週一至週日七個區段、今日與焦點標示、精簡摘要內容、類別色及新增日期。
- 每日先顯示 3 則，正確展開全部、收合及重設展開狀態。
- 月視角現有日期選取、記事詳情、每格 2 則及更多記事視窗不回歸。
- 載入、錯誤、重試與無結果狀態。

### App 整合測試

- 第一次預設月視角，保存與讀取最後模式，無效或不可讀偏好回退至月。
- 從其他主頁進入日曆以今天為焦點；日曆內深入並返回則保留模式、焦點與捲動位置。
- 模式切換保留焦點日期，三種箭頭按正確單位移動。
- 快速切換日期、模式或篩選時只採用最後請求。
- 登出、重新登入及更換資料空間後，舊日曆回應不能寫回。
- 搜尋篩選套用至三種模式及期間計數。
- 日／週新增預填日期；CRUD 成功刷新目前期間，失敗保留原畫面。
- 月視角點日期仍進入獨立單日清單，不切成日視角。

- 驗證跨月週、跨年週、月底月切換、今天及記事時區邊界。

## 已確認決策摘要

- 功能名稱由「月曆」改為「日曆」。
- 切換器位於日曆標題列紅框位置，選項為「日／週／月」。
- 切換模式保留焦點日期，最後模式保存在目前裝置，焦點日期不跨主頁切換或重新載入保存。
- 週一為每週第一天。
- 日視角使用完整摘要卡；週視角使用精簡摘要卡，1024px 以上排成七欄，手機與平板窄版改為七日直向區段。
- 週視角每一天先顯示 3 則記事，再於原日期區段展開或收合。
- 日與週視角都能新增指定日期記事。
- 月視角點日期維持既有獨立單日清單，不自動切換為日視角。
- 三種視角的內容與計數都反映目前篩選結果。
- 採用單一日期區間 API，Google Sheet schema 不變，舊日期／月份 API 暫時相容。
