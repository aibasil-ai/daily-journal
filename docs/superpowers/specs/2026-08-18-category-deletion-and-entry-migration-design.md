# 類別刪除與記事搬移設計

## 目標

讓使用者能在「類別管理」安全地永久刪除沒有任何記事的類別，並能先將某個類別底下的記事移至另一個啟用中的類別。

搬移功能必須支援：

- 從類別管理頁面啟動。
- 單筆記事移動。
- 勾選多筆記事後批次移動。
- 載入更多記事後仍保留先前頁面的勾選。
- 單筆及多筆操作都必須在確認後才寫入。

本功能不會刪除記事，也不支援「全選此類別所有記事」、刪除後復原或將記事移至停用類別。

## 已確認的產品規則

1. 類別只要仍有一筆以上的記事，就不可永久刪除；使用者可繼續使用既有的停用功能。
2. 類別記事數歸零後，才可永久刪除該類別。永久刪除會移除 `categories` 工作表中的該資料列，且不可復原。
3. 搬移目的地只能是啟用中的其他類別；來源類別不能作為目的地。
4. 使用者從類別管理的來源類別卡片開啟搬移面板。
5. 每筆記事提供獨立移動操作；多筆操作使用勾選框和批次工具列。
6. 已勾選的記事以 ID 保存在前端狀態中，因此分頁或載入更多時不會遺失選取。
7. 單筆與多筆搬移都要顯示來源、目的地及記事數量的確認對話框。

## 使用者介面

### 類別管理

類別卡片顯示由伺服器計算的完整記事數，而不是只計算目前時間軸載入的記事。

- 有記事的類別：顯示「搬移記事」；永久刪除控制項停用，並附上「請先搬移所有記事」的說明。編輯、停用與重新啟用行為維持既有規則。
- 沒有記事的類別：可按「永久刪除」。按下後顯示不可復原的確認對話框。
- 沒有其他啟用中類別時：仍可開啟搬移面板，但移動控制項不可用，並說明需先建立或重新啟用另一個類別。

### 搬移記事面板

面板標題顯示來源類別名稱與其完整記事數。內容使用現有記事排序與分頁規則，只查詢這個來源類別的記事，且不改變背景時間軸或月曆的篩選狀態。

每列顯示足以辨識記事的日期、標題／摘要與勾選框，並提供獨立的「移動」操作。批次工具列顯示已勾選筆數、目的地下拉選單與「移動已選記事」按鈕。目的地下拉選單只列出啟用中且非來源的類別。

- 單筆移動：按下某列的移動操作，選取目的地後開啟確認對話框。
- 多筆移動：使用者可跨已載入頁面勾選；工具列始終顯示總勾選數。確認成功後移除已搬走的列、清除其勾選，並更新來源類別的記事數。
- 行動裝置：面板以全螢幕或可捲動的對話層呈現，確保勾選、目的地選擇與確認按鈕可操作。

## 資料與 API 設計

### 類別管理摘要

`listCategories` 改回傳專用的類別管理資料，而不是僅回傳 `Category[]`：

```ts
type CategoryManagementData = {
  categories: Category[]
  entryCounts: Record<string, number>
}
```

後端從全部記事計算 `entryCounts`。前端的 `useJournal` 保存這份摘要，並將它傳給 `CategoryManager`。新增類別可在本機以計數 0 更新；搬移、刪除及重新取得類別時，必須重新讀取完整摘要。

### 讀取來源記事

搬移面板重用既有的 `listEntries` 請求，帶入來源類別的 `categoryId`、游標與頁面大小。面板持有獨立的列表、游標、載入狀態和 `Set<string>` 選取狀態，避免影響主畫面的記事清單。

### 新增寫入請求

新增以下 `ApiRequest` 動作：

```ts
{ action: 'moveEntries'; sourceCategoryId: string; targetCategoryId: string; entryIds: string[] }
{ action: 'deleteCategory'; id: string }
```

`moveEntries` 回傳已搬移筆數；`deleteCategory` 成功時不需回傳資料。單筆搬移使用相同的 `moveEntries` 請求，`entryIds` 只含一個 ID。

`JournalStore` 新增批次搬移與刪除類別的明確方法。Apps Script 實作必須以一個寫入鎖包住各自的作業：搬移時以批次方式更新所選記事的 `categoryId` 與 `updatedAt`；只有明確收到刪除請求且類別為空時，才刪除該類別的資料列。

## 伺服器端一致性規則

所有檢查與寫入皆在同一個 `withWriteLock` 區段中進行。

### `moveEntries`

伺服器必須先驗證：

1. `entryIds` 非空且沒有重複值。
2. 來源與目的地類別都存在。
3. 目的地為啟用中類別，且與來源不同。
4. 每個被選記事目前仍存在且屬於來源類別。

所有驗證通過後才進行批次寫入。若任一驗證失敗，整個請求不搬移任何記事，並以 `VALIDATION_ERROR`、`NOT_FOUND` 或 `CONFLICT` 回傳可理解的訊息。每筆成功搬移的記事都要更新 `updatedAt`。

### `deleteCategory`

伺服器必須確認類別存在，並在鎖內重新查詢是否有任何記事的 `categoryId` 指向它。只要仍有記事，回傳 `CONFLICT`；計數為 0 才呼叫 store 刪除類別。此檢查不可只依賴前端顯示的數量。

## 前端狀態與失敗處理

- 搬移或刪除成功後，重新讀取類別管理摘要，並重新載入受影響的主記事清單，讓篩選、卡片與月曆資訊一致。
- 單筆或批次搬移失敗時，面板保持開啟，跨頁勾選維持不變，並顯示服務端原因；使用者可刷新後重試。
- 若確認前選取的記事已被另一個操作搬走，整批搬移會被拒絕，不做部分搬移。
- 若目的地在確認前被停用或刪除，搬移被拒絕並要求重新選擇目的地。
- 刪除時若記事數量已改變，伺服器拒絕刪除；前端重新取得摘要並顯示最新狀態。
- 所有新增文案集中於 `src/i18n/zh-TW.ts`，確認對話框的初始焦點維持在取消按鈕。

## 元件與責任邊界

| 單元 | 責任 |
| --- | --- |
| `CategoryManager` | 顯示完整計數、類別操作入口與永久刪除確認；不自行讀寫記事。 |
| `CategoryEntryMovePanel`（新增） | 讀取來源記事、分頁、跨頁勾選、單筆／批次移動流程。 |
| `ConfirmDialog` | 沿用於永久刪除與搬移確認，僅管理對話層與焦點。 |
| `useJournal` | 保存類別管理摘要，公開取得摘要、搬移與刪除方法，並在成功後協調重新載入。 |
| `JournalService` | 驗證搬移與刪除規則，鎖定寫入範圍，對外提供明確領域操作。 |
| `JournalStore`／`AppsScriptJournalStore` | 執行 Google Sheets 的批次記事更新與類別列刪除，不承擔產品規則。 |

## 測試與驗收

### 自動化測試

- `JournalService`：非空類別拒絕刪除、空類別可刪除、單筆與多筆搬移、重複 ID／不同來源／停用目的地／相同目的地拒絕，以及失敗時沒有任何記事被搬移。
- dispatcher 與輸入驗證：新 API 動作、必要欄位與錯誤碼。
- store：批次更新正確更新 `categoryId` 與 `updatedAt`、刪除正確資料列、寫入鎖的行為。
- `useJournal`：更新摘要、成功後重新載入、失敗時保留畫面狀態。
- `CategoryManager` 與搬移面板：空／非空類別控制項、單筆確認、多筆跨頁保留、批次確認、無可用目的地與服務錯誤。

### 手動驗收

1. 建立兩個啟用類別與多則來源記事。
2. 驗證有記事的類別無法永久刪除，但仍可停用。
3. 從類別管理搬移一筆記事，確認來源計數、時間軸與月曆均更新。
4. 載入更多來源記事、跨頁勾選多筆並搬移，確認所有選取項目只搬移一次。
5. 將來源記事全部搬走後，確認永久刪除可用且確認後只移除空類別。
6. 嘗試選取停用類別作為目的地，以及在搬移前改變資料，確認系統給出清楚錯誤且不產生部分搬移。

## 非目標

- 不提供整個類別的「全選全部記事」功能。
- 不提供拖放搬移、搬移歷史、撤銷按鈕或軟刪除類別。
- 不變更既有記事永久刪除、分類停用或匯出規則。
