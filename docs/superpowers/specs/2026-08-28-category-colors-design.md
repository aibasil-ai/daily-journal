# 類別顏色與記事視覺同步設計

## 目標

讓使用者在類別管理頁快速設定固定的類別顏色，並將自訂顏色一致套用到類別卡片、時間軸、記事詳情與月曆記事。顏色永久保存在使用者自己的 Google Sheet，重新整理、重新登入或換裝置後仍維持一致。

本功能必須支援：

- 桌面版在類別卡片按滑鼠右鍵開啟色票。
- 類別卡片操作列提供調色盤按鈕，供手機、觸控及鍵盤使用者開啟相同色票。
- 類別未選自訂顏色時，保留每個畫面目前既有的預設底色。
- 類別選擇自訂顏色後，類別圖示、類別標籤及所有月曆記事使用完全相同的色碼。
- 既有 Google Sheet 自動且無感地升級，不遺失或重寫既有記事與類別資料列。

## 已確認的產品規則

1. 第一版只提供固定色票，不開放任意色碼或系統選色器。
2. 色票以參考圖的色系為基礎，排除深炭灰及任何無法搭配既有深色文字閱讀的顏色，並提供「預設」選項。
3. 所有自訂色與主要文字色 `#191c1e` 的 WCAG 對比至少為 4.5:1，文字不依底色切換成白色。套用自訂色時，原本使用 `--secondary-ink` 的類別標籤會明確改用 `--ink`；預設狀態仍保留各元件既有文字色。
4. 「預設」是未設定自訂色的特殊狀態，不是強制所有畫面使用同一色碼：
   - 類別卡片圓形圖示、時間軸標籤及記事詳情標籤維持既有淺藍 `#d0e1fb`。
   - 月曆日期格內的記事維持既有 `--surface-container`，目前為 `#eceef0`。
   - 月曆「更多」清單內的記事維持既有 `--surface-low`，目前為 `#f2f4f6`。
5. 選擇任一自訂色後，前述所有位置都改用該自訂色的完全相同色碼。
6. 類別卡片圓形背景改色後，中央資料夾圖示維持目前品牌藍。
7. 點選不同色塊後立即開始儲存，不需要額外按「儲存」；重選目前色塊只關閉色票，不送出請求或更新時間。
8. 已停用類別仍可修改顏色，歷史記事繼續顯示該類別的目前顏色。
9. 月曆日期格與某日超過兩筆記事時的「更多」清單都要套用類別顏色；「更多」按鈕本身不屬於任何單一類別，維持既有樣式。

## 使用者介面

### 開啟色票

類別卡片在非編輯狀態下支援兩個入口：

- 滑鼠右鍵：阻止該次瀏覽器預設選單，在游標附近開啟色票。
- 調色盤按鈕：在既有卡片操作列新增「設定類別顏色」，色票定位在按鈕附近。

兩個入口共用同一個 `CategoryColorMenu`。選單以固定定位顯示，開啟時依視窗邊界調整水平與垂直位置，不得被卡片或主內容的 overflow 裁切。行動裝置使用調色盤按鈕，不新增長按手勢。

### 色票內容與操作

- 標題為「類別顏色」，色塊採 8 欄圓形排列；窄螢幕可縮減欄數，但選項順序不變。
- 目前選項同時顯示外框與勾選標記，不能只依靠顏色表示選取狀態。
- 每個色塊都有繁體中文可存取名稱及 tooltip。
- 色票容器使用 `role="menu"`，色塊使用 `role="menuitemradio"`、`aria-checked` 及 roving `tabIndex`。調色盤按鈕以 `aria-haspopup="menu"` 標示可開啟選單。
- 方向鍵移動選項，Enter 或 Space 選色，Home 或 End 跳到首尾。
- Escape、點擊選單外部或切換頁面時關閉；從調色盤按鈕開啟時，關閉後焦點回到該按鈕。類別卡片設定 `tabIndex="-1"` 作為程式化焦點目標，從右鍵開啟時，關閉後焦點回到原類別卡片。

### 儲存回饋

點選不同色塊後立即關閉選單、在該類別卡片預覽新色並送出儲存請求。重選目前色塊只關閉選單並回復焦點。顏色儲存中的類別 ID 由 `useJournal` 維護，跨頁保留；同 ID 請求完成前，右鍵入口與調色盤按鈕不接受第二次顏色變更，避免較晚完成的舊請求覆蓋新選擇。按鈕以 `aria-busy` 與可存取文案表示儲存中。

- 成功：以伺服器回傳的完整 `Category` 取代前端狀態中的類別，預覽成為正式顏色，並以 `role="status"` 宣告更新完成。
- 失敗：清除預覽並恢復舊色；仍在類別管理頁時使用既有 `role="alert"` 錯誤區，已切換頁面時使用 `useJournal` 的全域錯誤狀態顯示原因。

### 各畫面顯示規則

| 顯示位置 | 未設定自訂色 | 已設定自訂色 |
| --- | --- | --- |
| 類別卡片圓形圖示背景 | `#d0e1fb` | 類別自訂色 |
| 時間軸類別標籤 | `#d0e1fb` | 類別自訂色 |
| 記事詳情類別標籤 | `#d0e1fb` | 類別自訂色 |
| 月曆日期格記事 | `--surface-container` | 類別自訂色 |
| 月曆「更多」清單記事 | `--surface-low` | 類別自訂色 |

月曆記事若有自訂色，hover 與 focus 時保留自訂背景，只改變外框或焦點樣式；未設定自訂色時維持既有 hover 與 focus 背景。類別標籤有自訂色時使用 `--ink` 作為文字色。找不到類別的異常記事一律使用該顯示位置的既有預設背景。

類別卡片中的品牌藍資料夾圖示維持 `aria-hidden`，屬於裝飾性圖示；類別名稱才是必要資訊。因此該圖示不作為色彩對比驗收目標。

## 資料模型與 API

### 共用型別

`Category` 新增可為 `null` 的 `color`：

```ts
type CategoryColor = typeof CATEGORY_COLORS[number]

type Category = {
  id: string
  name: string
  color: CategoryColor | null
  isActive: boolean
  createdAt: string
  updatedAt: string
}

type CategoryInput = {
  id?: string
  name: string
}
```

新增類別時 `color` 固定為 `null`；既有 `saveCategory` 只負責新增或改名，改名時永遠保留目前顏色。API 回應中的 `Category.color` 必須是 `null` 或白名單色碼。前端 API 邊界會正規化 bootstrap、類別清單及所有類別 mutation 回應；若舊傳輸層省略空值欄位，缺少的 `color` 一律轉為 `null`，不讓 `undefined` 進入應用程式狀態。

記事仍只保存 `categoryId`，不複製類別名稱或顏色。修改類別顏色後，所有既有記事會在下次 render 時取得目前色彩，不需修改任何記事資料列。

### 儲存流程

新增專用的 `setCategoryColor` action，避免改色請求攜帶可能已過期的類別名稱：

```ts
{ action: 'setCategoryColor'; id: string; color: CategoryColor | null }
```

- `color === null` 代表重設為預設狀態；字串則必須符合自訂色白名單。
- 請求不接受或套用 `name`，服務一律從目前儲存資料保留名稱、啟用狀態及建立時間。
- `JournalService.setCategoryColor` 驗證類別存在，只修改 `color` 與 `updatedAt`。
- 選取目前已選顏色時，前端不呼叫 action。
- `useJournal.setCategoryColor` 成功後只取代 `categories` 中的目標類別，不增加用於記事與月份資料失效的 `revision`。

## Google Sheet Schema 與遷移

### Schema v2

`categories` 工作表從五欄擴充為六欄，顏色只附加在最後，避免改變既有欄位位置：

```text
id, name, isActive, createdAt, updatedAt, color
```

`settings` 工作表的 `schemaVersion` 從 `1` 更新為 `2`。新建立的 Sheet 直接使用 v2。

Sheet 的 `color` 儲存規則：

- 空白：解析為 `null`，代表保留各畫面的既有預設色。
- 白名單色碼：解析為對應的 `CategoryColor`。
- 其他非空值：視為 `DATA_ERROR`，拒絕載入，不將任意值帶入 CSS。

### 既有 v1 自動遷移

系統只遷移完整符合下列條件的資料表：

1. 必要工作表名稱完整存在。
2. `entries`、`categories` 與 `settings` 標頭完全符合既有 v1。
3. `settings` 恰有一筆 `schemaVersion = 1`。
4. 所有既有記事與類別資料列都能以 v1 規則完整解析，且 ID 唯一。

全部唯讀驗證成功後，才用單一次 Google Sheets API v4 `spreadsheets.batchUpdate` 原子性執行：

1. 將 `categories!F1` 寫為 `color`。
2. 將既有 `schemaVersion` 值改為 `2`。

遷移不寫入任何類別資料列；既有空白 F 欄自然代表預設狀態。Google Sheets API 會先驗證 batch 中所有子請求，任一子請求無效時整批不套用。

遷移完成後重新以 v2 規則驗證並載入。v2 不重複遷移；未知版本、額外欄位、標頭順序不同、重複版本列或壞資料都維持現有安全策略，拒絕寫入且不猜測修復。

Vercel `SheetsJournalStore` 的初始化、連結驗證及一般載入共用同一套「確認或升級為目前 schema」流程。

公開使用者資料流程已不使用 GAS，因此仍參與建置的 `AppsScriptJournalStore` 只同步支援 v2 初始化、驗證、空白預設值及自訂色讀寫，不承擔 v1 自動遷移，也不引入 Advanced Sheets service。若直接以 GAS 連接 v1 Sheet，會清楚回報不支援的 schema；既有 v1 Sheet 的自動升級由 Vercel `SheetsJournalStore` 完成。

## 元件與責任邊界

| 單元 | 責任 |
| --- | --- |
| `shared/journal/category-colors` | 定義預設預覽色、自訂色白名單、型別與正規化驗證。 |
| `CategoryColorMenu` | 色票定位、選取狀態、鍵盤操作、外部點擊關閉及焦點回復；不直接呼叫 API。 |
| `CategoryManager` | 管理目前開啟類別、右鍵與按鈕入口、暫時預覽及頁面內錯誤回復。 |
| `useJournal` | 呼叫 `setCategoryColor`，跨頁保存儲存中的類別 ID，成功後只更新目標類別。 |
| `JournalService` | 驗證並執行獨立的類別顏色變更，只修改顏色與更新時間。 |
| `SheetsJournalStore`／`AppsScriptJournalStore` | 驗證 schema，解析與序列化 `color` 欄；只有 Vercel store 負責 v1 自動遷移。 |
| `Timeline`／`EntryCard` | 依 `categoryId` 傳遞並顯示類別名稱與顏色。 |
| `EntryDetail` | 顯示選取記事的類別名稱與顏色。 |
| `CalendarView` | 接收類別清單，為日期格記事與「更多」清單解析目前類別顏色。 |

顯示端以 CSS custom property `--category-color` 傳遞自訂背景色。沒有自訂色時不設定該 property，由各元件既有 CSS token 決定預設背景，藉此保留月曆與標籤不同的既有預設。

## 資料流

1. 使用者以右鍵或調色盤按鈕開啟某類別的色票。
2. `CategoryColorMenu` 顯示該類別目前的自訂色；`color === null` 時選取「預設」。
3. 使用者選色後，`CategoryManager` 關閉選單、設定卡片暫時預覽並呼叫 `setCategoryColor`。
4. API 驗證類別 ID 與顏色，`JournalService` 保留名稱與啟用狀態，只變更顏色及 `updatedAt`。
5. `SheetsJournalStore.flush()` 將該類別列的六欄內容寫回 Sheet。
6. 成功回應中的 `Category` 取代 `useJournal` 狀態中的同 ID 類別。
7. 時間軸、詳情與月曆依既有記事的 `categoryId` 取得更新後的顏色；顏色 mutation 不增加記事 `revision`，因此不重新請求或重寫記事與月份資料。

## 失敗與邊界處理

- 色碼不在白名單：前端不會產生此值；直接呼叫 API 時由伺服器以 `VALIDATION_ERROR` 拒絕。
- 選色期間類別被刪除：伺服器回傳找不到類別，前端恢復舊色並重新顯示錯誤。
- 儲存請求失敗：只清除暫時預覽，不修改其他類別或記事狀態。
- 使用者快速重複操作或切換頁面：`useJournal` 保存儲存中的類別 ID，同一類別在請求完成前不能再次送出顏色請求。
- 找不到記事對應類別：各畫面使用自己的既有預設背景，名稱沿用現有 fallback。
- v1 遷移驗證失敗：不送出任何寫入；v1 寫入 batch 失敗時，依 Google Sheets API 的原子性不留下半套 schema。
- v2 的非白名單顏色：拒絕載入並顯示資料錯誤，避免靜默改色或覆蓋使用者資料。

## 測試與驗收

### 自動化測試

- 色票常數：23 個自訂色皆唯一、格式正確，且與 `#191c1e` 的對比至少 4.5:1；深炭灰不在白名單。
- 輸入驗證與 `JournalService`：新類別預設為 `null`、改名保留顏色、設定自訂色、重設為 `null`、更新 `updatedAt`、重選目前顏色不發請求，以及拒絕任意色碼。
- In-memory store 與 dispatcher：`Category.color` 完整 round-trip，`setCategoryColor` 僅修改目標欄位；既有 `saveCategory` 不改變顏色。
- Vercel Sheets store：新 v2 初始化、v2 載入、空白顏色解析、色碼正規化、六欄寫回及顏色差異偵測。
- v1 遷移：精確 v1 成功升級、只改 F1 與版本、不重寫資料列、升級後重新驗證、v2 不重複升級。
- 遷移安全：壞資料、錯誤標頭、未知版本、重複版本列與非空不相容 Sheet 在送出 batch 前拒絕。
- GAS store：v2 初始化、預設值及自訂色讀寫，v1 明確拒絕且不寫入。
- `CategoryColorMenu`：右鍵與調色盤按鈕入口、目前選取、方向鍵、Enter／Space、Home／End、Escape、外部點擊與焦點回復。
- `CategoryManager`：停用類別可改色、即時預覽、成功保留、失敗回復與錯誤警示、儲存中禁止同類別重複選色。
- `EntryCard`／`EntryDetail`：預設背景與自訂背景。
- `CalendarView`：日期格及「更多」清單的預設背景、自訂背景、找不到類別 fallback，以及「更多」按鈕維持既有樣式。
- `useJournal`／App：API 回應缺少顏色時正規化為 `null`；成功後只更新目標類別且不增加記事 `revision`；儲存中 ID 跨頁保留；既有記事及月份資料不重新請求，切換畫面後顏色一致。

### 手動驗收

1. 以既有 v1 Sheet 登入，確認自動升級為 v2，所有原類別、記事及時間保持不變。
2. 建立兩個類別，一個維持預設，一個選擇自訂色。
3. 桌面版在類別卡片按右鍵選色，確認選單位置、即時預覽及重新整理後持久化。
4. 使用調色盤按鈕及純鍵盤完成選色、重設預設、Escape 關閉與焦點回復。
5. 手機版透過調色盤按鈕選色，確認色票未超出視窗且所有選項可觸控。
6. 確認預設類別的圖示與標籤維持淺藍，月曆日期格維持灰色；自訂類別在所有位置使用相同自訂色。
7. 確認時間軸、記事詳情、月曆日期格及「更多」清單都顯示正確類別色。
8. 停用類別後改色，確認歷史記事立即反映且仍可重設為預設。
9. 模擬儲存失敗，確認卡片恢復舊色並顯示錯誤，其他畫面資料不變。

## 非目標

- 不提供任意色碼、系統選色器、吸管工具、漸層或透明度。
- 不依底色自動切換白字，也不提供不符合對比要求的深色。
- 不提供手機長按開啟色票。
- 不從時間軸、記事詳情或月曆直接修改類別顏色。
- 不讓單篇記事覆寫所屬類別顏色。
- 不保存記事建立當時的歷史類別色；類別改色會影響該類別所有既有記事。
- 不變更類別停用、刪除、記事搬移、搜尋或 CSV 匯出規則。
- 不替已停用且不再作為公開資料路徑的 GAS v1 Sheet 實作自動遷移。

## 實作分段

本規格仍是單一「類別顏色」功能，但實作計畫應分成三個有順序的檢查點，每個檢查點完成對應自動化測試後再進入下一段：

1. 共用型別、`setCategoryColor`、Vercel schema v2 與安全遷移，以及 GAS v2 相容。
2. `useJournal` 儲存狀態、`CategoryColorMenu`、類別卡片入口與改色回饋。
3. 時間軸、記事詳情、月曆日期格及「更多」清單的顏色呈現。
